# v14.11 — ㅈ 두 획·곰 그림·업데이트 설명

## 실제 수정

- legacy BASIC_STROKES와 게임 단계 쓰기 JAMO의 ㅈ을 두 획으로 변경: 가로줄에서 오른쪽 끝까지 간 뒤 왼쪽 아래로 한 번에 이어 긋고, 교차점에서 오른쪽 아래로 두 번째 획. 자·조 등 초성, 짖·잊 등 받침에 공통 반영. ㅉ은 두 개의 2획 ㅈ(4획), ㅊ은 맨 위 획 + 같은 2획 구조(3획)로 일관화. 관련 글자의 총 획 수/시작점/화살표도 데이터에서 함께 변경된다.
- 두 엔진 traceEvaluation 함수는 바이트 단위로 유지하고 SHA-256 기준값을 기록. 일부만 긋기/역방향/모서리 잘라 긋기/누락 획 통과를 허용하지 않는다. 글자·낱말 전체 완료 조건, 3회 발음·진도·쓰기 연습 설정·5분 규칙 유지.
- 꿀을 먹는 곰은 원본 출력에 옆 장면과 흰 구분선이 섞인 잘못된 아틀라스 잘림이었다. 내장 이미지 도구로 동일한 곰·노란 목도리·꿀단지를 한 장면으로 실제 다시 제작. 양쪽 귀/손/발·단지 전체와 숲 여백 확인. 새 파일명으로 제공하여 오래된 HTTP 캐시 그림과 구분. 이미 열려 있는 구버전이 깨지지 않도록 옛 URL은 호환용으로 남기되 현재 수업은 새 완성 장면만 참조한다.
- 업데이트 숫자는 실제 저장 완료 파일 수/전체 파일 수. 파일 수 기준 퍼센트와 progress 요소, 설명 문장을 추가. ‘닫고 배경에서 준비하기’는 설치를 취소하지 않는다. 앱을 켜 둔 동안 파일 준비가 진행되고 완료 시 홈에 적용 버튼 안내. 기존 놀이 중에는 강제 새로고침하지 않으며 ‘업데이트하기’를 누르면 실제 worker 버전을 확인하고 적용한다. 앱을 완전히 종료한 뒤 OS가 계속 처리한다고 보장하지 않는다.

## 이미지 거절에 대해 확인한 사실

새 스파이더맨 구조 삽화 응답: HTTP400, `moderation_blocked`, `moderation_stage: output`, `categories: [other]`, request `0dd57cd2-f806-47d7-859d-07acc9116239`. 세부 판정 조건·정책 변경 이력은 응답이나 사용 가능한 도구에서 조회할 수 없다. 이용자 승인 부족, 별도 결제 요구, 계정 한도, 전체 이미지 기능 불능으로 단정할 근거가 없다. 이전 캐릭터 이미지 성공 기록과 이번 곰 편집 성공 모두 존재한다. 과거 성공만으로 새 생성 결과의 심사 통과가 보장되지는 않는다. 사용자 승인은 있으나 도구의 출력 심사를 해제할 권한은 없다. 거절된 캐릭터 콘텐츠를 우회/재시도하지 않았으며 해당 삽화는 여전히 미완료다.

## 검증과 환경 제한

- qa/v13/jieut.cjs: 2개 엔진 ㅈ 2획, 초성/종성/겹받침/쌍자음 획 수, 온전한 경로 인정·가로줄만/역방향/모서리 생략 거부 및 evaluator 기준 해시.
- qa/v13/jieut_bear.py: 실제 Chrome 390×844/1280×800 마우스 입력으로 기본 자(4획)와 게임 단계 ㅈ(2획) 끝까지 쓰기. 일부만 쓰면 미완료, 모음도 필수. 새 곰 이미지 decode·꿀 정답·다음 버튼 확인. 스플래시 제거 후 화면 직접 확인.
- qa/v13/update_runtime.py: 실제 구 worker→새 worker 이전, 배경 완료 안내, 파일3640/4375(83%) 설명, meter 값, 닫기·시간 초과·offline·legacy flag·실제 캐시 음원 재생. 실제 교체 후에는 controllerchange 전달을 막아 두어도 적용에 성공함을 검증(두 번째 이벤트 대기에 의존하지 않음).
- 240개 학습 그림 연결/138개 고유 장면 검사 및 static smoke 통과.
- 로컬 전체 browser smoke: 최초에는 새 word-gate 캐시 쿼리를 옛 테스트가 기대하여 실패, 올바른 새 쿼리 요구로 갱신. 이후 Chrome이 `Resource temporarily unavailable`, `Zygote could not fork`와 빈 DOM으로 실패. 환경에서 종료 프로세스 약27,000개 누적 확인. 검사 기준을 낮추거나 SKIP을 통과로 처리하지 않았다. 실제 변경 기능의 정상 브라우저 입력/미디어 검증은 이 환경 문제가 발생하기 전에 통과했다.
